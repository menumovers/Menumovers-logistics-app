If the database schema gets synced to match the new code before the existing role data is captured somewhere else first, that data is just gone — Postgres drops the column, full stop.

snapshot-user-roles.ts — must run FIRST, while users.role still exists in the live database. It copies each user's current role into a plain backup table called _role_backfill.
backfill-user-roles.ts — must run AFTER the schema has been updated (i.e., after user_roles exists and users.role is gone). It reads _role_backfill, inserts the corresponding rows into user_roles, and then deletes the backup table.
